### 4. DÉFAUT CORRIGÉ — les drop-ins d'intervalle ne remplaçaient rien

Repéré à l'armement : `gdrive` annonçait son prochain run dans 27 min, au
lieu d'1 h.

**Cause : les directives de temps de systemd s'ACCUMULENT.** Un
`OnUnitActiveSec=` dans un drop-in s'AJOUTE à celui du gabarit, il ne le
remplace pas ; systemd retient ensuite le déclenchement le plus proche.

```
$ systemctl --user show gdrive-sync@gdrive.timer -p TimersMonotonic
  OnUnitActiveUSec=1h        ← le drop-in
  OnUnitActiveUSec=30min     ← le gabarit, jamais retiré  → c'est lui qui gagnait
```

`gdrive2` masquait le défaut : drop-in et gabarit valent tous deux 30 min,
donc aucun écart visible. **Seule la paire dont l'intervalle diffère du
gabarit était touchée.**

Correctif dans le générateur (`DROPIN`, `~/.local/bin/gdrive-sync`) — la
ligne vide réinitialise la liste avant d'y remettre la valeur :

```ini
OnUnitActiveSec=
OnUnitActiveSec={interval}
RandomizedDelaySec=
RandomizedDelaySec={jitter}
```

Drop-ins régénérés par `gdrive-sync install-units`, puis `daemon-reload`.
Vérification :

```
gdrive   OnUnitActiveUSec=1h      RandomizedDelayUSec=10min   next 07:46:56
gdrive2  OnUnitActiveUSec=30min   RandomizedDelayUSec=5min    next 07:15:14
```

`OnBootSec=3min` est bien resté dans le gabarit et `Persistent=yes` est
actif ; il n'apparaît plus dans `TimersMonotonic` parce qu'il a déjà été
consommé pour ce démarrage. Il reprendra au prochain boot.

Sauvegarde du binaire avant correctif dans le scratchpad de séance.

### 5. Rétention des archives — N = 30, outil écrit et armé

Décision de Flavien : **N = 30**, aligné sur `log_keep_days`.

Le moteur n'a toujours aucune rétention d'archives — `prune_logs` ne
concerne que les logs. Outil écrit : **`~/.local/bin/gdrive-archives-prune`**
(755, 5 690 o), hors dépôt.

- Parcourt les paires de `config.toml`, côté local **et** distant.
- Se fie au **nom** du dossier (`AAAAMMJJ-HHMMSS`), pas au mtime — côté
  Drive le mtime d'un dossier ne veut rien dire.
- **Essai à blanc par défaut**, `--apply` pour agir. Aussi `--days N` et
  `--local-only` (n'ouvre pas le trousseau).
- Distant purgé avec `--drive-use-trash=false`.

Vérifié dans les deux sens sans rien toucher :

```
$ gdrive-archives-prune              → 0 à purger, 2 gardés  (15 j et 11 j)
$ gdrive-archives-prune --days 5     → 2 à purger, 0 gardé
```

Timer quotidien posé et activé :

```
~/.config/systemd/user/gdrive-archives-prune.service   (Environment=GDS_ARCHIVE_KEEP_DAYS=30)
~/.config/systemd/user/gdrive-archives-prune.timer     (OnCalendar=daily, RandomizedDelaySec=30min, Persistent=true)
```

**C'est une suppression automatique non surveillée.** Pour l'arrêter :
`systemctl --user disable --now gdrive-archives-prune.timer`.
